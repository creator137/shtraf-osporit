# Стадия 1: фундамент и базовый продукт

## Цель стадии

Подготовить рабочий каркас сервиса «Штраф.Оспорить»: пользователь взаимодействует с Telegram-ботом, создаёт дело и загружает постановление, а администратор видит пользователей, дела и документы в простой web-панели.

Стадия 1 не включает автоматический анализ постановления и подготовку жалобы. На этой стадии система только принимает и сохраняет исходные данные.

## Обязательный функционал

### Telegram-бот

- Команда `/start`.
- Регистрация пользователя по Telegram ID.
- Обновление имени, фамилии и username при повторном `/start`.
- Главное меню.
- Раздел «Оспорить штраф».
- Перед загрузкой постановления показывается согласие на обработку персональных данных.
- Без согласия загрузка постановления и создание дела невозможны.
- Создание нового дела.
- Приём документов:
  - PDF;
  - JPG/JPEG;
  - PNG;
  - фотографии, отправленные из Telegram.
- Сохранение документа локально.
- Во внешнем интерфейсе Telegram хранится только file_id как временный компромисс до отдельного файлового хранилища.
- Привязка документа к делу.
- Изменение статуса дела после загрузки документа.
- Раздел «Мои дела».
- Просмотр списка дел пользователя.
- Просмотр базовой информации по делу.
- Раздел «Помощь» с описанием доступных возможностей.

### Backend

- Python 3.12.
- aiogram 3 для Telegram-бота.
- FastAPI для HTTP API.
- PostgreSQL как база данных.
- SQLAlchemy 2 для работы с базой.
- Alembic для миграций.
- Pydantic для конфигурации и API-схем.
- pytest для тестирования.

### Модели данных

Необходимо реализовать три основные сущности:

#### User

- внутренний идентификатор;
- Telegram ID;
- username;
- имя;
- фамилия;
- дата регистрации;
- дата обновления.

#### Case

- внутренний идентификатор;
- пользователь-владелец;
- статус;
- дата создания;
- дата обновления.

Минимальные статусы:

- `DOCUMENT_UPLOADED` — документ загружен;
- `IN_PROGRESS` — документ в работе;
- `READY` — дело готово.

#### Document

- внутренний идентификатор;
- дело;
- Telegram file ID;
- исходное имя файла;
- MIME-тип;
- путь к локальному файлу;
- дата загрузки.

#### UserConsent

- внутренний идентификатор;
- пользователь;
- Telegram ID;
- версия согласия;
- дата и время принятия.

### Административная панель

Админка должна включать:

- страницу пользователей;
- список зарегистрированных пользователей;
- Telegram ID, имя, username и количество дел;
- страницу дел;
- список дел с пользователем, статусом, количеством документов и датой создания;
- страницу подробностей дела;
- информацию о пользователе;
- статус и даты дела;
- список загруженных документов;
- просмотр и скачивание загруженных документов;
- изменение статуса дела;
- состояния загрузки, ошибки и пустые списки.

### Admin API

Минимальные endpoints:

- `GET /health`;
- `GET /admin/users`;
- `GET /admin/cases`;
- `GET /admin/cases/{case_id}`.
- `PATCH /admin/cases/{case_id}/status`;
- `GET /admin/documents/{document_id}/file`.

### Документы и согласия

Подробное описание того, какие данные собираем, где храним, кто имеет доступ и
как удаляется дело, вынесено в [docs/DOCUMENTS_AND_CONSENTS.md](./DOCUMENTS_AND_CONSENTS.md).

## Требования к инфраструктуре

- Локальный PostgreSQL должен запускаться без ручного создания таблиц.
- Все изменения схемы базы должны выполняться через Alembic.
- Секреты должны храниться только в `.env`.
- `.env` не должен попадать в Git.
- Backend, админка и бот должны запускаться независимо.
- Для Telegram polling должна использоваться только одна активная инстанция бота на один токен.

## Проверка готовности

Стадия 1 считается готовой, если:

- PostgreSQL запускается локально;
- миграции применяются командой `uv run alembic upgrade head`;
- backend запускается через Uvicorn;
- `GET /health` возвращает `{"status": "ok"}`;
- все backend-тесты проходят;
- админка запускается через Vite;
- страницы пользователей, дел и деталей дела открываются;
- пользователь появляется в базе сразу после `/start`;
- согласие на обработку персональных данных сохраняется в базе перед загрузкой постановления;
- после загрузки документа дело имеет статус `DOCUMENT_UPLOADED`;
- документ виден в Telegram и в админке;
- пользователь видит только свои дела;
- повторная регистрация по тому же Telegram ID не создаёт дубликат.

## Что не входит в Стадию 1

Следующие задачи относятся к будущим стадиям и не должны реализовываться сейчас:

- OCR;
- распознавание полей постановления;
- автоматическое извлечение данных о штрафе;
- ручная коррекция распознанных данных;
- LLM;
- интеграция с OpenAI, Claude или Gemini;
- юридическая база знаний;
- Legal Rules Engine;
- автоматический юридический анализ;
- проверка качества фотографии камерой;
- генерация жалобы;
- генерация DOCX или PDF;
- платежи;
- передача дела юристу;
- сложные роли и права доступа;
- сложная аналитика.

## Порядок запуска локально

1. Создать `.env` на основе `.env.example`.
2. Запустить PostgreSQL.
3. Установить backend-зависимости:

   ```bash
   cd backend
   uv sync
   ```

4. Применить миграции:

   ```bash
   uv run alembic upgrade head
   ```

5. Запустить API:

   ```bash
   uv run uvicorn app.api.main:app --reload --port 8000
   ```

6. Установить зависимости админки и запустить её:

   ```bash
   cd admin
   npm install
   npm run dev
   ```

7. Запустить Telegram-бота:

   ```bash
   cd backend
   uv run python -m app.bot.main
   ```

8. Проверить интерфейс:

   - админка: `http://localhost:5173`;
   - API: `http://localhost:8000`;
   - Swagger: `http://localhost:8000/docs`.
